# AI 택시 합승 매칭 및 경로 최적화

22101162 컴퓨터공학과 김중겸

서울 노원구의 OpenStreetMap 도로망을 사용해 승객을 합승 그룹으로 묶고, 승·하차 순서와 가상 요금을 비교하는 Python 프로토타입입니다. Streamlit 화면에서 가상 요청, 좌표/CSV, 주소 검색을 선택할 수 있습니다.


## 주요 기능

- OSMnx로 노원구 차량 도로망을 다운로드하고 GraphML 파일로 캐시합니다. 첫 실행에 인터넷 연결이 필요하고, 다음 실행부터 로컬 캐시를 재사용합니다.
- 도로 거리를 기준으로 최단 경로를 계산하고, 도로 유형별 가정 평균 속도로 이동 시간을 추정합니다.
- 승객별 허용 우회 시간(0~30분), 택시 인원(2~4명), 승차 선행, 도로 연결 여부를 합승 제약으로 적용합니다.
- 가까운 출발지, 경로 방향 유사도, 거리·우회 효율의 세 매칭 기준을 제공합니다.
- Exact search, Greedy, Genetic Algorithm, OR-Tools 경로를 비교합니다.
- 승객별 개별/합승 예상 시간과 가상 부담 요금, 경로·승하차 순서를 지도와 표로 보여줍니다.
- 가상 수요 자료로 Random Forest 예측 시연을 합니다. 이 기능은 핵심 최적화와 별도 모듈입니다.
- 실행 요약은 프로젝트 폴더의 SQLite 파일에 로컬 저장합니다.

## 사용 기술 및 버전

검증 환경은 Python 3.13.17, Windows x64입니다. 직접 의존성 버전은 `requirements.txt`에 고정했습니다.

- Python, Pandas, NumPy
- OSMnx, NetworkX, GeoPandas, Shapely
- Streamlit, Folium, streamlit-folium
- OR-Tools, Plotly, Matplotlib
- scikit-learn, SQLite

## 설치 및 실행

Windows PowerShell에서 저장소 폴더로 이동해 실행합니다.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

브라우저에서 Streamlit이 출력한 주소를 엽니다. 첫 실행에 노원구 경계와 도로망을 내려받습니다. 다운로드가 실패하면 앱에 오류가 표시되며, 연결을 확인한 뒤 다시 실행하면 됩니다. 네트워크 캐시, GraphML, SQLite 파일은 Git에 포함되지 않습니다.

## 사용 방법

1. 왼쪽에서 `가상 요청`, `좌표/CSV 입력`, `주소 검색` 중 하나를 선택합니다.
2. 택시 탑승 인원, 매칭 기준, 요금 할인 설정을 고릅니다.
3. `경로와 합승 최적화`를 누르면 지도, 합승 그룹, 경로 순서, 승객별 시간·요금, 알고리즘 비교를 확인할 수 있습니다.
4. `이전 실행` 탭에서 이 컴퓨터에 저장된 최근 실행 요약을 확인합니다.
5. `수요 예측 시연` 탭의 결과는 실제 호출량이 아니라 가상 자료를 이용한 설명용 결과입니다.

CSV 예제는 [`data/sample_passengers.csv`](data/sample_passengers.csv)입니다. 좌표 입력에는 다음 열이 필요합니다.

| 열 | 설명 |
|---|---|
| `passenger_id` | 화면에 표시할 승객 ID |
| `pickup_lat`, `pickup_lon` | 노원구 안 출발 위도·경도 |
| `dropoff_lat`, `dropoff_lon` | 목적지 위도·경도 |
| `max_detour_min` | 허용 우회 시간(0~30분) |
| `requested_at` | 호출 희망 시각(선택) |
| `share_allowed` | 합승 허용 여부 |

주소 검색은 입력한 주소를 좌표로 바꾸기 위해 OpenStreetMap Nominatim에 요청합니다. OSM 공개 서비스로 주소를 전송하지 않으려면 좌표 또는 CSV 입력을 이용하세요. 이름, 전화번호 등 개인정보나 비공개 주소를 넣지 마세요. Nominatim 요청 결과는 OSMnx 캐시에 저장되고, OSMnx가 요청 간격을 조절합니다. Nominatim 사용 정책상 공개 서비스는 초당 1회 이하로 사용해야 합니다.

도로 데이터는 `data/road_network/` 아래 로컬에 저장되며, 시뮬레이션 요약과 승객 좌표는 `data/simulations.sqlite3`에 저장됩니다. 주소 문자열, 이름, 전화번호는 DB에 기록하지 않습니다. DB와 좌표는 이 컴퓨터에만 두며, 공개 저장소에 올리지 마세요. 지도 배경 타일은 브라우저가 OpenStreetMap 타일 서버에서 불러옵니다.

## 최적화와 계산 방식

- **매칭 후보**: 각 승객의 가까운 출발지 이웃(기본 최대 6명)을 사용해 최대 4명 후보를 만들고, exact route 검사로 연결성·승차/하차 순서·최대 인원·개별 우회 한도를 확인합니다. 선택된 그룹들은 매칭 기준에 따라 정렬한 뒤 겹치지 않도록 순서대로 고르는 휴리스틱입니다. 전 승객을 대상으로 한 전역 최적 set-packing 해법은 아닙니다.
- **Exact search**: 4명 이하 그룹의 승·하차 순서를 제약에 맞춰 열거해 가장 짧은 경로를 고릅니다. 소규모 그룹용 기준 해법입니다.
- **Greedy**: 현재 위치에서 갈 수 있는 승차/하차 지점 중 가까운 합법적 정차 지점을 고릅니다.
- **Genetic Algorithm**: 제약에 맞는 순서를 만들고, 선택·교차·변이로 경로 후보를 탐색합니다. 유전 알고리즘은 항상 최적해를 보장하지 않습니다.
- **OR-Tools**: Pickup-and-Delivery 및 Capacity 제약, 승객별 탑승 시간 제한을 사용합니다. 결과는 동일한 경로 평가기로 다시 검증합니다.

시간은 OSM 도로 유형별 가정 속도에서 계산하며 실시간 정체나 신호 대기, 승하차 시간을 반영하지 않습니다. 도로망에 연결되지 않은 구간은 경로 후보에서 제외됩니다.

## 가상 요금

기본 개별 예상 요금은 아래 식으로 계산하고 100원 단위로 반올림합니다.

```text
기본요금 4,800원 (2026년 기준 서울택시 기본요금)
+ max(0, 도로거리(km) - 1.6km) × 1,000원
+ 예상시간(분) × 80원
```

합승 할인율은 `max(0, 개별 이동거리 합 - 합승 경로 거리) / 개별 이동거리 합`에 할인 배수를 곱한 뒤, 설정한 할인 상한(기본 30%)으로 제한합니다. 할인된 총액은 각 승객의 개별 예상 요금 비율을 기준으로 나누고, 반올림 잔액은 마지막 승객에게 배정합니다. 이는 동작 설명을 위한 가상 모델이며 서울시의 공식 요금표가 아닙니다.

## 테스트

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

테스트는 승차 선행, 탑승 인원, 우회 제약, 요금 배분, 매칭, Greedy/Genetic/OR-Tools, SQLite 저장, 합승 시간 요약, 가상 수요 예측을 검사합니다. 통합 검증에서는 내려받은 노원구 도로망으로 5명 샘플의 승객별 경로와 알고리즘 결과를 계산했습니다.

## 승객 수별 시연 성능

같은 가상 요청 20건(seed=2026)에서 처음 5·10·15·20건을 차례로 계산했습니다. 시간은 이미 내려받은 OSM 도로망에서 `optimize_passengers`를 실행한 벽시계 시간이며, PC 사양·캐시 상태에 따라 달라집니다. 합승 후보 검색과 네 경로 알고리즘을 포함합니다. 전체 수치는 [`data/benchmark_results.csv`](data/benchmark_results.csv)에 있습니다.

| 승객 | 계산 시간(초) | 유효 후보 | 선택 그룹 | 합승 인원 | Greedy 성공 | Genetic·OR-Tools·Exact 성공 |
|---:|---:|---:|---:|---:|---:|---:|
| 5 | 2.283 | 15 | 1 | 2 | 1/1 | 각각 1/1 |
| 10 | 10.053 | 158 | 4 | 9 | 3/4 | 각각 4/4 |
| 15 | 16.052 | 252 | 5 | 14 | 3/5 | 각각 5/5 |
| 20 | 19.811 | 269 | 6 | 17 | 5/6 | 각각 6/6 |

Greedy는 일부 선택 그룹에서 제약을 충족하는 전체 순서를 찾지 못했습니다. 이는 비교 대상으로 드러난 휴리스틱의 한계이며, 최종 표시 경로는 Exact search가 찾은 제약 충족 경로를 사용했습니다.

## 한계 및 다음 단계

- 노원구 내 실제 OSM 도로의 완전성이나 위치 스냅 정확도에 따라 결과가 달라질 수 있습니다.
- 차량 운행 시간은 평균 속도 가정이라 교통 예측으로 사용할 수 없습니다.
- 기본 요금표, 거리 기준, 할인 배분은 실험용 가정입니다.
- 매칭 그룹 선택은 휴리스틱이고, Exact search도 각 고정 후보 그룹만 최적화합니다.
- 수요 예측 데이터는 완전히 가상입니다. 실제 수요 예측에는 시간대·지역별 과거 호출 데이터와 별도 검증이 필요합니다.
- 향후 교통 API, 실제 운임 정책, 개인정보 보호를 검토한 운영용 지오코더와 글로벌 매칭 해법을 연결할 수 있습니다.
